  - Phase 4a design defaults (signed off 2026-11-19 as written, including migration 0006 core_user_login_id_unique):
    - (a) Passwords: argon2id via hash-wasm 4.12.0, encoded output, 16-byte random salt, memory 19456 KiB, 2 iterations, parallelism 1, 32-byte hash. Stored in core_user.password_hash. Policy: 12 to 128 characters, no composition rules, must differ from login_id.
    - (b) PINs: 4 to 6 digits, hashed with the same argon2id settings into core_user.pin_hash. 4a has the hashing and verify functions only. No PIN login endpoint until the PIN use decision is made.
    - (c) Login: POST /auth/login with the X-Tenant-Id header, loginId and password. Only users with status active can log in. Wrong password, unknown login, locked and inactive users all get the same 401 AUTH_INVALID_CREDENTIALS. Unknown logins still run an argon2 verify so response time does not reveal them.
    - (d) Lockout: 5 consecutive failures lock the user for 15 minutes (locked_until). A successful login resets the count. Rate limits per IP and per login are Phase 4b.
    - (e) login_id is unique per tenant (migration 0006 adds core_user_login_id_unique). The handoff does not state this, so it needs sign-off.
    - (f) Access token: JWT signed HS256 with jose 6.2.15, 15-minute lifetime. Claims: sub (user id), sid (session id), tid (tenant id). Key from JWT_SECRET (at least 32 characters). JWT_SECRET is required when NODE_ENV is production. In other modes a random key per process is used and a warning is logged.
    - (g) Refresh token: 32 random bytes, base64url, returned once. Only the SHA-256 hash is stored, in core_user_session.refresh_hash. Fixed 30-day lifetime (not sliding). Each refresh rotates: the old session is revoked and a new one is issued with the same expiry. Presenting a revoked refresh token revokes every active session of that user (reuse detection).
    - (h) Every protected request checks the JWT and that its session is not revoked or expired, so logout takes effect at once.
    - (i) POST /auth/refresh takes the refresh token in the body. POST /auth/logout revokes the current session. GET /auth/me returns the current user.
    - (j) Auth events are written to core_auth_activity (login_success, login_failure, login_locked, refresh, refresh_reuse, logout). ip_address stays NULL until the owner sets the raw IP retention period. Changes to core_user login state are not written to audit_row_change in 4a; this needs a decision.
