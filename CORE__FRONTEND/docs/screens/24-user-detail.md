# 24 User detail (new user, and view or edit a user)

Source: `src/modules/organisation/pages/UserDetail.tsx`, `src/modules/organisation/components/UserForm.tsx`, `PRIVILEGES` in `core-data/data/seed.ts`

## 1. Purpose
Creates a CORE user, or shows and edits one user: their details, role, modules, scope and privileges. It also shows where they sit in approval chains, and their change history.

## 2. Route & access
- Paths: `/users/new` and `/users/:id`.
- Access: Tenant Admin. Granting privileges needs **step-up**.
- An unknown ID shows "User not found".

## 3. Data displayed
| Card | Data |
|---|---|
| Person | name, email, phone, designation, loginId, status, lastLogin, mustChangePassword |
| Role and access | role, modules, scope (Company, or a list of project codes), privileges grouped by module |
| In the approval matrix | each chain where the user is an approver in the latest version: request type, level, scope |
| Change history | audit entries where `entity === 'User'` and `entityId === user.id`: time, action, before, after |

The privilege catalogue (`PRIVILEGES`) lists, per module:
- `*.users.manage`, `*.requests.raise`, `*.reports.view`, `*.approve`;
- plus `pms.payments.release` and `stores.transfer.raise`.

## 4. User actions
| Control | Effect |
|---|---|
| Back | Goes to `/users`. |
| Create user (new) | `saveUser` with a new uuid, `mustChangePassword = true`, `lastLogin = null`. See below. |
| Edit, then Save | `saveUser`. Shows "User saved". |
| Reset password | The same dialog as [23](23-users-and-roles.md). |
| Deactivate or Reactivate | The same dialog as [23](23-users-and-roles.md). |
| Open chain (matrix card) | Goes to `/approval-matrix/:chainId`. |

After Create user, the app shows "User created. A temporary password was emailed." and goes to `/users/:id`.

If any privilege is added, saving first asks for **step-up** ("Grant N privileges to <name>"). Cancelling stops the save.

## 5. Forms & validation
| Field | Required | Rule and message |
|---|---|---|
| name | yes | at most 80 |
| designation | yes | "Designation is required." |
| email | yes | a valid email. Unique: "Another user has this email." |
| phone | yes | `^[6-9]\d{9}$` |
| loginId | yes | `^[A-Za-z0-9]{3,6}\d{4}$`: "Use 3–6 letters or digits followed by 4 digits, for example VELOX1234." Unique, ignoring case: "Another user has this login ID." Upper-cased on save. A new user gets a suggested next ID (`nextLoginId`). |
| status | yes | `Active` or `Inactive` |
| role | yes | `Module head` or `Approver` |
| modules | module head: at least 1 | "Choose at least one module this person heads." See below. |
| scopeType | yes | `Company` or `Project` |
| scopeIds | when Project: at least 1 | "Choose at least one project." |
| privileges | — | only from the chosen modules. Cleared for approvers. |

A module that already has another active head is refused: "<module> already has an active head (<name>). Deactivate them first or untick that module; each module has one active head."

## 6. Existing API calls
None.

## 7. Backend requirements (inferred)
**GET `/api/v1/users/{id}`** returns `CoreUser`.

**GET `/api/v1/users/{id}/approver-of`** returns `{ "items": [{ "chainId": "AC-7", "requestType": "Material", "level": 2, "scopeType": "Project", "scopeIds": ["P-101"] }] }`.

**GET `/api/v1/audit?entity=User&entityId={id}`**: see [38](38-audit-trail.md).

**GET `/api/v1/users/next-login-id`** returns `{ "loginId": "VELOX1189" }`.

**POST `/api/v1/users`**
```json
{ "name": "Priya Sharma", "designation": "HR Manager", "email": "priya@veloxiq.example", "phone": "9876543210", "loginId": "VELOX1189",
  "role": "Module head", "modules": ["HRMS"], "scopeType": "Company", "scopeIds": [], "privileges": ["hrms.users.manage", "hrms.approve"], "status": "Active" }
```
201 returns `CoreUser`. It emails a temporary password and sets `mustChangePassword`.

**PUT `/api/v1/users/{id}`**: same body. Needs `X-Step-Up-Token` when privileges are added.

| Status | Code |
|---|---|
| 409 | `EMAIL_TAKEN`, `LOGIN_ID_TAKEN` |
| 409 | `MODULE_HEAD_TAKEN` (with module and holder) |
| 401 | `STEP_UP_REQUIRED` |
| 422 | field errors, `PRIVILEGE_NOT_IN_MODULE` |

## 8. State & side effects
- Audit entries, which the save splits by what changed:
  - "Module head created" or "High-level approver created";
  - "Role changed";
  - "User deactivated" or "User reactivated";
  - "Privileges changed (step-up verified)";
  - "Modules or scope changed";
  - "Contact details changed".
- An email with the temporary password.
